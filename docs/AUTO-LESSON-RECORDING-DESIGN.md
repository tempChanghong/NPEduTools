# 根据 ClassIsland 课表自动录课：构思与可行性

设计日期：2026-09-17。本文保留完整目标与实施顺序，不代表所有功能均已交付。

2026-09-18 更新：第一阶段“今日计划与预演”已实现，详情见 [使用与实现记录](AUTO-LESSON-RECORDING-PREVIEW.md)。已读取真实 ClassIsland 日程并验证预演；尚未接入自动采集，也未修改 ClassIsland 本体或用户课表。

## 1. 建议的产品行为

可以实现。由 ClassIsland 提供当前生效的课程及时间安排，NPEduTools 根据用户选择生成逐节录制计划，调用已有独立录制器。

默认将“二分钟铃”解释为课表上课前两分钟。用户也可以选择跟随 ClassIsland 的课前提醒，但两者在技术上并不相同，后者需要额外提供有效提醒设置或真实提醒信号。

每节课的目标窗口为：

```text
目标开始 = 本节课开始时间 − 提前量（默认 2 分钟）
目标结束 = 本节课结束时间 + 课后余量（可选 0～5 分钟，默认 5 分钟）
```

课表没有老师实际结束讲课的信号。因此“最多五分钟”在第一版应当意味着：默认自动保留五分钟，老师可以提前按“结束本节”，到上限自动停止。不能仅凭安静、退出 PPT 或下课事件认定老师已经讲完。

| 示例：数学课 10:00–10:40 | 行为 |
| --- | --- |
| 09:58 | 自动开始，显示“数学 · 自动录制” |
| 10:00 | 继续录制 |
| 10:40 | 进入课后余量，显示“下课后继续录制，剩余 05:00” |
| 10:42 老师点击结束 | 结束并保存，本节不再自动开启 |
| 没有手动操作 | 10:45 请求停止，随后完成文件保存 |

停止时刻指停止采集的目标时刻，保存 MP4 可以稍后完成。现有 FFmpeg 启动和退出有延迟，应记录目标时间与实际首/末帧时间；不能承诺毫秒级准确或完全无缝。

```mermaid
flowchart LR
    A[等待所选课程] --> B[课前两分钟：开始]
    B --> C[课中：持续录制]
    C --> D[到下课时间：课后余量]
    D --> E[手动结束或到五分钟上限]
    E --> F[保存并标记本节完成]
```

## 2. 用户如何配置

主窗口增加“自动录课”管理页；侧边栏展示当前状态和当天快捷操作。

| 配置 | 建议 |
| --- | --- |
| 总开关 | 默认关闭；用户启用后按已选课程执行 |
| 课程来源 | 当前连接的 ClassIsland 生效课表 |
| 录制范围 | 全部课程，或按星期、科目、节次、时间范围筛选 |
| 匹配方式 | 单条规则中的条件同时满足，多条规则取并集；同一节只生成一个任务 |
| 当天覆盖 | “今天不录”“跳过本节”“仅今天录这节”优先于常规规则 |
| 课前提前量 | 默认 2 分钟；界面清楚区分固定提前量和跟随提醒 |
| 课后余量 | 0～5 分钟，默认 5 分钟 |
| 画质、音源、保存目录 | 复用现有独立录制设置；与手动录制可使用不同预设 |
| 今日计划 | 显示科目、正式课时、实际计划录制窗口、匹配规则、跳过/冲突原因 |
| 预演模式 | 只记录“此时应开始/结束”，不打开录音或屏幕采集 |

科目筛选保存科目 ID，名称仅用于显示；不能用“数学”这样的名称作为唯一身份。停用的课程不录制；课间、分割线、行动时间点不当作课程。

侧边栏可显示“下次：明天第 1 节语文，07:58 开始”“正在录制数学，预计 10:45 结束”；提供暂停/继续、结束本节、今天不再自动录制。暂停不推迟绝对结束时间，避免暂停五分钟后又把课后窗口延长五分钟。

### NPEduTools 已具备

`ClassIslandProbe` 已读取当前状态、科目、计时器/课表是否启用、当前时间点索引，并订阅四种公开 IPC 通知；持续监听会周期性重新读取，支持断线重连。录制器已有开始、暂停、继续、结束、保存和片段恢复能力。

### 尚未具备

当前 `LessonStatusDto` 没有每节课的开始/结束、科目 ID、完整日程、课表身份与版本、ClassIsland 当前有效时间。现有事件计数只描述本次连接中观察到的事件，不能充当“某节课已经录过”的记录。

因此无法仅在当前 `OnClass` 和 `OnBreakingTime` 处理器中加两个录制按钮调用，就得到可靠的自动录课。尤其下课事件应进入余量，而不是直接停止。

### 上游公开接口可提供的材料

| 接口/字段 | 用途与限制 |
| --- | --- |
| `IPublicLessonsService.CurrentClassPlan` | 当前实际选中的课表；应优先于自己根据星期推算 |
| `GetClassPlanByDate(date)` | 预览指定日期的计划；返回值可能为空，不能保证未来计划不会变化 |
| `CurrentTimeLayoutItem` / `NextClassTimeLayoutItem` | 当前/当前或下一节的时间段；后者在上课时也可能指当前课 |
| `NextClassSubject` | 与下一课程时间点一起验证，不能把课间名称误作下一课科目 |
| `OnClassLeftTime` | 距上课倒计时，可以辅助固定提前两分钟的触发及时间一致性检查 |
| `IPublicProfileService.Profile` | 档案中的课表、时间表和科目映射；设计只读取，不调用保存/换课方法 |
| `TimeLayoutItem.StartTime / EndTime / TimeType` | 日内时间和类型；0 为课程，1 课间，2 分割线，3 行动 |

重要限制：`ClassPlan.TimeLayout`、`ValidTimeLayoutItems`，以及 `ClassInfo.Index/CurrentTimeLayoutItem` 等是带 `JsonIgnore` 的运行时属性。不能假定收到 `CurrentClassPlan` 后，直接遍历这些计算属性就能得到完整正确日程。

无插件路径应在隔离适配进程内读取实际传输的数据，按 `TimeLayoutId` 从档案查时间表，再把 `TimeType == 0` 的条目按顺序与 `Classes` 对齐，并考虑 `IsEnabled`。还需要核实该版本 IPC 的真实序列化结果、空值与集合变化；本次只确认源码和契约存在，尚未实测这个新增日程快照。

`CurrentSelectedIndex` 是整个时间表的索引，不等于过滤课间后的课程序号。`OnBreakingTimeLeftTime` 在当前实现中依赖下一课间的开始时间，不能替代当前课程 `EndTime`，尤其最后一节后没有显式课间时。

## 4. “二分钟铃”与时间基准

公开 `IpcRoutedNotifyIds` 只有上课、课间、放学、时间状态变化四项，没有专门的“课前两分钟提醒开始”事件。

真正的课前提醒在 `ClassNotificationProvider` 中，根据倒计时、提醒开关、室内/室外提前量及附加设置计算。`PrepareOnClass` 枚举的存在也不能证明外部进程会收到该状态。铃声可能来自其他软件或校园广播；课表只能预测其时刻，不能证明物理铃声已经响起。

另外，`LessonsService` 使用 `IExactTimeService`，它可能采用 NTP、手动时间偏移和调试偏移，甚至在系统时间突变时短暂冻结返回时间。直接用 Windows `DateTime.Now` 比较课表有可能与屏幕上的倒计时不一致。

建议：

1. 第一版提供固定提前 2 分钟模式，验证倒计时和课程边界的一致性；无可靠时间基准时暂停新任务，说明原因。
2. 精确跟随 ClassIsland 时，桥接提供同一快照里的“ClassIsland 当前有效时间＋有效日程＋有效提醒提前量”；提醒是否实际展示/播放需要另有明确语义，不能把“计划提醒时刻”标成“铃已响”。
3. 已开始的任务保存一个有上限的停止期限，并使用单调计时器约束最长持续时间。时间回拨或连接重建不能无限延长录制。

## 5. 接入路线

建议先扩展现有 IPC，完成只读快照和预演验证；只有当实际接口无法可靠提供所需信息时，增加轻量桥接插件。录制引擎继续在 NPEduTools 中运行。

| 方案 | 优点 | 需要解决 |
| --- | --- | --- |
| 现有 IPC 扩展 | 沿用已有连接和隔离进程，不要求安装插件 | 档案序列化、课表身份、多个属性跨时刻读取、精确时间一致性 |
| ClassIsland 桥接插件 | 可以从本体取得生效日程、精确时间，在合适的主循环阶段生成快照 | 插件安装与版本兼容；快照更新、提醒语义仍需验证 |

插件只生成扁平的日程/时间快照，不在 ClassIsland 主进程中加载音频、GDI 或 FFmpeg。插件按 ClassIsland 的目标框架构建；不能直接引用 NPEduTools 的 .NET 10 程序集，采用共同兼容的协议定义或独立 JSON 契约。

```mermaid
flowchart LR
    CI[ClassIsland 当前生效日程] --> Adapter[已有 IPC 适配器 / 可选桥接插件]
    Adapter --> Snapshot[有版本的扁平日程快照]
    Snapshot --> Planner[规则筛选与今日预览]
    Planner --> Scheduler[调度、去重与人工覆盖]
    Scheduler --> Recorder[NPEduTools 独立录制器]
    Recorder --> Files[视频 / 任务记录 / 恢复片段]
```

快照应包含档案身份、可确认的课表身份、课程日期、时间表身份、课程时段、科目 ID/名称、启用状态、生成时刻、时钟基准和本地版本号。`CurrentClassPlan` 本身不直接提供档案字典中的课表键；匹配不唯一时不能仅按名称猜测，应报告无法确定或使用桥接。

原有 IPC 的多个 getter 不是原子快照。读取前后校验课表与时段锚点、必要时重读，可减少混合数据，但不等于上游事务保证；跨临时换课及配置修改的可靠性应实测。不要把整个 Profile 直接塞进 NPEduTools 当前 64 KB 的消息帧，先在适配器中提取、限制并验证日程 DTO。

## 6. 必须明确的边界行为

| 情况 | 建议的第一版行为 |
| --- | --- |
| 下课但老师拖堂 | 继续到配置的余量上限；可手动提前结束 |
| 暂停录制 | 暂停采集，不顺延结束期限 |
| 手动“结束本节” | 持久化本节已结束；轮询、重连和重启不再自动开录这节 |
| 手动录制正在进行 | 自动任务不抢占，不停止手动会话；显示本节因占用跳过 |
| 关闭录制/管理窗口 | 按现有行为保持后台运行；显示可见的自动录制状态 |
| 完整退出程序 | 停止并保存当前会话；以后课程不会凭空唤醒已退出程序，需用户配置已有登录启动 |
| ClassIsland 断线 | 不开始新的自动任务；已录制任务按保存的停止期限结束，不一直等下课事件 |
| 重连/程序在课中启动 | 可配置补录；建议仅在正式上课期间且读到新鲜有效快照时补录，标明缺失开头 |
| 仅在课后余量期间启动 | 默认不新建录制，避免只录到课间 |
| 临时换课/临时层 | 重新生成尚未开始的任务；按当前生效科目匹配用户规则 |
| 当前正在录的课被修改 | 显示变更；取消课程可停止自动会话，普通换名不切碎视频，不能因此无限延后上限 |
| 课表禁用或当天无课 | 不启动；明确停课/取消与单纯通讯中断要区分 |
| 时间回拨、电脑休眠 | 唤醒后重新校验日程，不重放过期触发；用记录去重并约束总时长 |
| 设备或磁盘故障 | 沿用现有录制失败与片段保留机制，不标记成成功录完 |

“已结束/已跳过”要按具体的课程发生实例记录，不能只按科目名、事件计数或连接 ID。推荐保存日期、档案/时间表、课程时段及任务身份，并把课表修订与任务身份分开。临时层换 ID 或改科目时，仍需把任务映射到已经结束的同一节，避免手动停止后又被新版本课表重开。

### 相邻课程的窗口重叠

若课间小于 7 分钟，前一节的“后 5 分钟”可能碰到后一节的“前 2 分钟”。当前录制器只允许一个会话，且停录重封装再启动会有间隙，不能宣称每节都能无缝拿到完整重叠窗口。

第一版建议在预览中提示并采用“下一节优先”的分界：在不截断前一节正式课时的前提下，缩短前一节课后余量，让出下一节的课前窗口。若课表本身重叠或连堂导致无法满足两者，则标记冲突，提供手动合并或选择一节，不悄悄并发两个编码器。

若用户要求连堂无缝且每节文件都有完整前后余量，应另行实现“连续采集、分段留存、事后按课程窗口导出”。这涉及关键帧和片段边界，属于后续录制引擎升级，不能只靠现有 start/stop 调度实现。

## 7. 实施顺序与验收

1. **只读日程快照**：扩展适配器和严格代理超时设置，在已有 ClassIsland 本体/私有测试环境验证课程、时间表、临时换课、课间索引、最后一节和空课表；先决定是否需要桥接。
2. **今日计划与预演**：完成筛选、前后余量、冲突提示、去重和人工覆盖，预演只输出应执行的动作。
3. **接入录制器**：任务携带明确的所有权与自动结束期限，由录制工作进程也执行截止约束；不能只有 WPF 中的一个定时器负责停录。
4. **真实联调**：用短模拟课表验证完整流，再在目标大屏进行整课录制。

关键验收：提前两分钟触发；下课不立即停止；到五分钟上限结束；暂停不延长；手动停止不重启；断线后仍按期停止；临时换课更新待录计划；同科目连续两节可区分；默认不接管手动录制；时间跳变不重复；窄课间有明确冲突处理；保存失败能找到片段。

2026-09-17 的设计阶段完成了源码核对与本文；2026-09-18 的实现与验证范围请以 [预演阶段记录](AUTO-LESSON-RECORDING-PREVIEW.md) 为准。真实自动录课尚未验收，现有手动录制验证不能代替完整调度与采集验收。
