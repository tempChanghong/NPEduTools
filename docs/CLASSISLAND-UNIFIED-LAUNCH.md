# ClassIsland 统一启动

日期：2026-09-06。首页和贴边快捷面板共用同一个启动流程，管理员自启动设置继续负责创建、更新和删除任务。

## 用户行为

| 当前状态 | 点击“启动”后的行为 |
| --- | --- |
| 未运行，匹配的管理员任务已启用 | 运行现有计划任务，检查程序路径、用户、会话和管理员权限 |
| 未运行，没有任务或任务已禁用 | 普通启动；仅当 Windows 返回“需要提升权限”时请求 UAC |
| 已以管理员身份运行 | 复用当前实例，确认课程连接，不重复启动 |
| 已普通运行，管理员任务已启用 | 显示原因，并把按钮改为“管理员重启”；再次点击才请求 UAC 和正常退出 |
| 已普通运行，未启用管理员任务 | 复用当前实例并确认课程连接 |
| 任务冲突、实例身份不明或查询失败 | 显示原因，不猜测权限或启动其他任务 |

现有任务的执行若明确返回访问被拒绝，可通过 UAC 重试同一个任务；授权前后比较任务指纹。排队或运行中的任务不重复提交。任务条件未满足、手动运行被禁用或启动结果不明确时不改用普通启动，也不自动再次提交。运行现有任务不会创建、更新或删除自启动配置。

取消管理员重启授权时，普通实例继续运行，按钮仍可用于再次请求。重启前仍执行已有的用户、路径、会话和正常退出检查。管理员自启动的管理页面保持原有功能。

## 启动与就绪分开验证

独立组件负责启动方式选择与进程权限检查。确认进程存在后，App 请求 Host 的 `classisland.verify` 验证课程接口，并保存原有执行记录。这项能力检查配置版本及路径，只验证当前进程；如果进程已退出，返回失败，不重新启动。

Host 改用有限权限查询进程路径，可从普通权限核实已有管理员 ClassIsland。首页与快捷面板显示启动进度、需要重启的原因和验证结果；成功后的新实时快照接管快捷面板状态，避免后续断连仍显示旧的成功信息。

启动失败或通信结果不明确不会自动重放。验证阶段的记录仍存储在现有启动记录中；进程操作发生在独立组件，其失败不会虚构为已就绪记录。原有 CLI `classisland.start` 保持原语义，本次统一入口范围是桌面主窗口和快捷面板。

调用现有任务使用 Task Scheduler `RunEx`，限定当前交互会话，并检查 `AllowDemandStart`。依据：[RunEx 官方说明](https://learn.microsoft.com/en-us/windows/win32/taskschd/registeredtask-runex)、[允许按需启动](https://learn.microsoft.com/en-us/windows/win32/taskschd/taskschedulerschema-allowstartondemand-settingstype-element)。
