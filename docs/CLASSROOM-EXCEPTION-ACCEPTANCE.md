# 课堂模式异常实机验收

日期：2026-09-20。接续 [正常往返验收](EXAMAWARE2-PACKAGED-ACCEPTANCE.md)。状态：本轮验收和配置清理已完成，有未通过项目，详见下文。

## 当前结论

发版决策补充（InDev 20260920）：用户确认日常使用会先关闭考试编辑器，因此本版暂缓修复上游退出问题，将其列入发版说明和安装指南的已知限制。此决定不改变下表的未通过结果；未来支持编辑器仍打开时切换，需要重新完成内容保存、取消和重试验收。

**不能将异常场景整体判定为通过。** NPEduTools 能识别退出未确认、桥接断开和 ClassIsland 未就绪，保留未完成记录、暂停自动录课，并支持恢复连接后的显式重试。但本机构建的 ExamAware2 1.5.2 在编辑器打开时退出，会提前卸载插件和 IPC，导致编辑器无法正常保存、关闭。这个上游问题阻断了“保全编辑内容后直接重试”的完整流程。

本轮使用当前用户配置、实际 Release Host、原生 Windows 任务和 Run 自启动登记，以及上轮从用户源码构建的 ExamAware.exe。考试内容均为本次临时生成。未修改两款软件的产品代码，也未修改 Windows 安全设置。

模式调用通过生产命名管道提交，与界面使用相同服务。编辑器故障测试刻意在仅含临时数据的窗口仍打开时提交等效保存确认，以验证不满足前提时的防护；不是对用户真实考试内容的保存声明。本轮不重复计算整个 WPF 界面的按钮验收。

## 编辑器问题的实际影响

19:25 的原生取消关闭测试成功。19:26 返回日常时，日志先记录桥接卸载，随后出现 `dialog:show-message-box` 错误；主窗口消失，但编辑器留在内存。后续 Ctrl+S 显示保存失败，退出结果保持 `Unconfirmed`。

这意味着“不会强行结束进程”虽然成立，却不能据此承诺未保存内容已安全落盘。现有提示中“请保存并关闭编辑器后重试”在这个故障发生后不足以帮助用户完成恢复。

代码链路与 [E3 报告](EXAMAWARE2-STAGE3.md) 一致：上游 `shutdownCoordinator.ts` 在再次调用 `app.quit()` 前清理 IPC 和插件；`editorWindow.ts` 拦截关闭，需要渲染端通过同一批接口完成保存确认和关闭。完整修复应先处理编辑器退出协商，再进行不可逆的退出清理；NPEduTools 不应以强制结束进程替代这一步。

为继续验收，先保存了可见测试内容的人工重建副本 `editor-content-rescue.json`，随后只清理本轮启动、身份核实过的故障 ExamAware 测试实例（PID 54820）。这次**测试夹具强制清理**明确记录在 `fixture-teardown.json`，不属于产品退出流程，不计作成功保存或正常退出；没有真实考试文件参与。

另有一条需独立复核的现象：首次修改备注后直接 Ctrl+W，编辑器日志判断 `isFileModified=false` 并关闭，磁盘文件未写入这段备注。该字段的更新依赖 blur；本轮将其记为输入尚未提交时的关闭问题，不能将“屏幕上有新文字”等同于模型已进入未保存状态。随后通过添加测试考试建立明确未保存状态，原生取消测试才有效。

## 另一项界面发现

后台正常停止后，主页触摸辅助区域显示“后台已停止，请退出后重新打开”，但模式卡仍显示上一次“日常模式”。本轮通过后台接口运行测试，不能将残留的模式卡当作实时状态。源码中 `WatchAsync` 收到停止事件后取消共享 lifetime；`ClassroomModePollAsync` 若正处于轮询间隔，会直接退出而没有清空上次展示，存在这一时序。应补齐后台停止时主窗口与侧边栏统一更新为未知/不可用的路径，再做界面回归。

本轮只记录上述发现，没有修改产品代码。优先顺序为：先处理 ExamAware 编辑器退出协商和未保存内容保全，再修复后台停止后的模式卡显示；之后补测真正处于考试时间内、启用学校退出限制策略的放映场景。
