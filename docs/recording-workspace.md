# 录课工作区

录课在主窗口中统一为“立即录制、自动安排、录制记录”。全屏自习展示、管理验证、录制器和音频容错策略不因这次布局调整改变。

## 日常操作

- **立即录制**：默认显示当前画面、声音和目录摘要；“修改录制设置”展开原有屏幕、画质、帧率、系统声音、麦克风、目录和设备检测。开始后收起配置，显示时长、后台状态和暂停／继续、停止并保存。录制过程中不重新探测设备。
- **自动安排**：默认显示当天有效课程；选课后“这天录制并保存／这天不录并保存”提交日期覆盖。取消覆盖恢复继承。每周规则仍可配置多个规则、跟随课表或固定时段、生效日期、星期、科目、节次和课前／课后余量。排除名单、科目长期覆盖、暂停日期、仅显式单日安排、指定日期固定时段和试运行均保留。
- **启用**：保存设置和安排不会开启自动录课。开启总开关仍由 Host 检查保存的录制选项、学校时间、模式暂停、当前占用和其他约束。切页、收起主窗口不会停录；完整退出仍遵守原停止和租约保护规则。
- **跳过与停止**：“跳过下一节”使用独立的 `skip-upcoming` 操作，只提交下一项未处理计划的跳过记录；“停止当前录制”携带当前会话控制标识。旧快捷侧栏使用的 `skip-next` 混合操作保留兼容。两个入口不再用同一个命令表达不同意图。
- **记录**：显示 Host 返回的最近一次录课状态、视频或保留片段位置，以及最近自动执行账本，可筛选全部、需要处理和已保存。这里只展示现有后台返回范围，不是扫描所有历史视频的完整文件库。试运行记录与实际记录分开。相同账本轮询不重建列表，以保留阅读位置。

## 生命周期与布局

主窗口复用已有 `RecordingWindow` 和 `AutoRecordingWindow` 控制器，通过 `WorkspacePanel` 嵌入它们的内容，不打开重复录制窗口或创建第二个录制客户端。隐藏页面不调用 `Shutdown` 或发送录制停止／自动停用；主窗口真正关闭时才执行已有清理。设备探测只用在首次空闲进入或主动刷新；先进入已有录课的页面，待录课结束后才补一次设备探测。文件夹对话框使用实际主窗口作为所有者。

背景录制与租约继续由 `RecordingClient` 和 Host 管理。丢失回执或失联时，禁用未确认的控制并标明状态未知；不得用上次成功数据覆盖未知状态。仅新鲜回执恢复控制。

状态查询必须成功且包含录制与自动安排两份快照；缺少字段或管理租约被拒绝时撤回确认，保留旧会话标识用于重新核对，不重放开始或停止命令。操作回执只确认实际返回的部分。停止后台并退出不能把旧的空闲状态或单独的“自动开关已关闭”当作录制已完成；需等待当前状态确认。“今天不再录制”和其他自动操作在失联或等待命令回执时统一禁用，快捷侧栏也隐藏未确认的暂停入口。

页面继承主窗口密度设置。课程表改为三列的可换行信息；小窗口可以纵向滚动，底部后台操作保留。逻辑 1280×700 和 1024×540 分别覆盖 2K／全高清屏幕在 200% 缩放附近的可用空间；这不是实机 DPI 和触控验收的替代。

## 隔离验证

```powershell
./scripts/test-desktop-field-fixes.ps1
./scripts/dotnet.ps1 test tests/NPEduTools.Tests -c Release -p:RestoreLockedMode=true -m:1
```

桌面回归脚本包含 `recording-workspace`、`manual-recording`、`automatic-recording`、`recording-plan-save` 和 `automatic-recovery`，并继续运行自习、校准、窗口密度与边界等原有回归。

录课工作区测试加载正式 WPF 页面，使用私有测试 Named Pipe、合成设备与学校时钟回执；它验证协议请求、会话控制、导航、掉线恢复、设置与规则文件的隔离保存，以及紧凑布局。后台测试直接验证 `skip-upcoming` 的账本持久化与不停止当前自动会话。测试不启动真实麦克风、系统音频、屏幕录像或生产服务。

实机待验证：一体机在 200% 缩放时的触控滚动、设备探测、后台长课时录制、暂停恢复、文件收尾，以及配套 App/Host 更新后的学校课表执行。本轮不发版。
