| --- | --- |
| 主交付 | 按用途展示引导，加入考试环境、学校互联、噪音监测；可直接完成学校配对 |
| 布局 | 用途卡片、当前步骤标签、固定底部导航、内容区可滚动 |
| 准备入口 | 对接已有偏好、ClassIsland、考试看板、课堂模式、学校互联和噪音窗口 |
| 授权说明 | 明确配对后的状态上报、通知遮罩、远程模式与自启动、监测及排程；不是新隐私协议 |
| 状态语义 | 考试／噪音步骤只读准备状态；学校步骤由用户主动申请及确认；“已了解”不等于环境就绪 |

实现：`OnboardingState.cs` 管理用途和进度，`OnboardingWindow.xaml` 展示，`OnboardingWindow.Preparation.cs` 只读考试／噪音准备状态；`MainWindow.Onboarding.cs` 连接现有管理入口。

学校配对使用同一个 `NpepConnectionControl` 和 `NpepConnectionSession`，供引导与设置页共用。Host 仍负责配对、后台轮询、持久化与凭据，界面不复制这套机制。后续已加入[学校预授权与网页生成码](NPEP-PREAUTHORIZED-PAIRING-20261002.md)，作为推荐路线；以下图描述仍保留的旧审批方式。

```mermaid
flowchart LR
    A[填写服务地址和设备名称] --> B[检查服务并核对实例]
    B --> C[主动创建配对码]
    C --> D[管理员批准学校和班级大屏归属]
    D --> E[本机核对归属和连接功能]
    E --> F[确认配对]
    F --> G[显示已配对和当前连接状态]
```

可以跳过学校步骤、稍后设置；不会取消已有申请。再次打开时读取后台保留的申请与归属，已有配对不重新登记。配对过期需取消旧申请后再创建；未完成的创建／确认操作使用恢复入口。已配对但离线或暂停可以通过本步，正在处理或未完成配对不能被标为已完成。学校、班级、大屏由批准信息提供，不提供本机自行填写归属的入口。

界面显示时每秒读取 Host 状态，由 Host 继续访问学校服务。两个窗口共用操作锁；正在处理时禁止重复命令。后台响应丢失会清除可操作快照，先刷新核实结果。服务身份或批准归属变化会取消旧勾选；解绑确认也核对版本，避免对变化后的归属执行旧确认。只读刷新保留文本框焦点与正在编辑的地址。

HTTP 仍可使用，说明传输不加密并优先推荐 HTTPS。确认页解释状态、通知、模式与自启动、考试方案、监测统计和排程授权；正式隐私协议仍待另行制定，这份功能说明不冒充协议。

验证：引导进度与共享配对会话测试共 48 项通过，含旧记录、断点继续、跳过、归属变化、失联、并发请求与恢复，以及后台未连接时填写地址、已有申请／绑定时显示提供商与重新配对；隔离输出目录编译通过（0 警告／0 错误）。八个页面完成默认与最小尺寸的离线 WPF 预览，学校页另检查服务已核对、等待批准、待确认、已配对及滚动到底部的布局；示例状态不代表设备验收。测试回执：`.artifacts/onboarding-refresh/tests/school-onboarding.trx`。旧 UI 脚本更新了完成后的首页预期，本轮没有运行原生 UI 自动化。

地址入口修正：服务提供商地址始终显示，不再随配对状态整体隐藏。未配对或后台尚未连接时可填写地址；后台未确认时仍不能发起请求。已有申请或绑定显示可复制的只读当前地址，并提供“更换服务提供商…”入口；显式确认取消申请／解绑后才恢复输入，不会静默替换旧服务。两处入口同步生效。

人工查看：Visual Studio Debug 后进入 **设置 → 常规 → 初始设置**，勾选学校互联，使用本地测试服务走完“检查 → 创建码 → 网页批准 → 本机确认”；等待阶段关闭引导，再从设置页继续，核对是同一申请。检查返回／跳过、已有配对离线时继续、以及完成汇总。真实人工配对尚待执行；未启动真实录制、麦克风或考试切换，也未执行生产操作、提交或推送。
