# NPEP 诊断摘要对照 · 2026-10-04

| 任务卡 | 内容 |
| --- | --- |
| 主交付 | NPEduTools 导入学校诊断 JSON，在本机对照两端记录并给出排查建议 |
| 用途 | 定位服务／归属不一致、上报暂停、TLS 错误、观测过时及模式差异 |
| 边界 | 只读文件和现有缓存；不上传文件、不修改配对、不重新探测或控制软件 |
| 状态 | 本地实现与自动化验收通过；真实桌面交互、大屏和生产验收未执行 |

## 怎么使用

1. 在网页 **学校管理 → 大屏设备 → NPEP 设备互联 → 学校运维概览**，搜索并加载对应设备，点击 **导出诊断摘要**。
2. 在 NPEduTools **设置 → 学校互联 → 故障排查**，点击 **对照学校诊断摘要…**，选择该 JSON。OOBE 复用同一连接控件。
3. 页面显示服务、学校、班级和大屏绑定是否匹配，以及两份观测的 UTC 时间和排查建议。结果不会自动刷新；需要时重新导出并对照。

结果代表两份记录的对照，不是当前运行状态、物理电脑身份或授权有效性的证明。学校最近收到上报的时间单独显示；诊断元数据使用 UTC，不影响 ClassIsland 时间与排程。

| 情况 | 如何处理 |
| --- | --- |
| 服务或学校、班级不同 | 提示核对 API 地址与归属，不建议直接重新配对 |
| 文件中找不到大屏 | 提示检查搜索、筛选和分页；不判定为未配对 |
| 同一大屏存在多份登记 | 不自动挑选在线或历史登记；管理员缩小导出范围后重试 |
| 登记已撤销、过期或失效 | 先核对登记与授权，不继续比较运行状态 |
| 观测超过一分钟或时间基准存疑 | 明确提示旧记录／时间不确定，不把一致性当作当前正常 |
| 上报暂停、网络或 TLS 错误 | 给出具体检查入口，不关闭证书校验 |
| 模式、录制不同或缺失 | 提示核实与刷新，不判定切换失败或强行停止录制 |
| 桥接未就绪 | 按学校观测到的模式解释：日常关注 ClassIsland，考试关注 ExamAware2 |

切换服务或归属、解除绑定、控件卸载时清空旧结果并取消正在进行的对照。普通状态刷新不会把已有对照伪装成新结果。导出和对照共享操作保护，避免并发读取。

## 输入与实现

接受 `schemaVersion=1`、`kind=npep-school-overview-diagnostics` 的网页摘要，最多 2 MiB、200 条设备记录、32 层 JSON；支持 UTF-8 BOM。校验计数、字段类型和重复键。无效文件在读取本机状态前拒绝；原文件不修改。只显示程序生成的提示和解析后的时间，不直接回显文件中的自由文本。

- `src/NPEduTools.App/NpepDiagnosticComparison.cs`：有界文件读取、解析、归属匹配、新鲜度判断和排查建议。
- `NpepConnectionControl.xaml(.cs)`：选择文件、显示结果及生命周期清理。
- `NpepConnectionSession.CollectDiagnosticsAsync`：沿用 `npep.status` 与 `host.cached-status`，增加调用方取消支持；仍不执行控制命令。
- `tests/NPEduTools.Tests/NpepDiagnosticComparisonTests.cs`：格式、归属、时间、状态、取消和跨仓库摘要回归。
- `scripts/test-npep-operations.ps1`：统一验收新增 `comparison-contract` 阶段，先执行两端真实导出代码，再由 C# 对照本轮生成的四组摘要。CI 上传白名单增加这一步的结果。

网页与后端业务代码本轮未修改，NPEssentials 未修改。
