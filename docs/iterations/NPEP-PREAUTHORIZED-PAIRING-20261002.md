# NPEP：先授权，再在大屏配对

2026-10-02 · 下一版本的本地实现；未提交、推送或部署。

**这轮的交付：学校提前按单屏、年级或全校开放网页配对，现场安装人员自行完成连接，无需管理员同时在线。** 预授权只允许新设备申请连接；短码兑换后，NPEduTools 仍显示学校、班级和大屏，现场核对功能范围并确认。

```mermaid
flowchart LR
  A[学校管理员开放班级大屏] --> B[对应大屏网页登录]
  B --> C[生成一次性配对码]
  C --> D[NPEduTools 输入后端地址和配对码]
  D --> E[显示固定学校班级大屏归属]
  E --> F[本机确认连接]
  F --> G[后台上报并接收学校功能]
```

| 操作 | 入口与效果 |
| --- | --- |
| 提前开放 | 学校管理 → NPEP 设备互联 → 班级大屏预授权；先建立有效学期、班级和大屏账号 |
| 批量开放／关闭 | 同一位置 → 按年级／全校批量设置 → 选择范围与操作 → 预览 → 核对并勾选确认 → 提交 |
| 获取码 | 对应班级大屏登录 NPClassworks → 课堂工具 → 连接 NPEduTools；页面同时显示后端服务地址 |
| 现场连接 | NPEduTools 初始设置的学校步骤，或设置 → 学校互联；填写地址、检查服务、输入网页码、核对归属并确认 |
| 关闭预授权 | 阻止新网页配对，使未完成申请失效；不会断开已连接设备 |
| 撤销已连接设备 | 学校后台的撤销互联设备授权；预授权开关与已有设备授权分别管理 |
| 兼容旧流程 | 桌面“其他方式：由管理员逐次批准”仍可生成码，交由管理员指定归属；旧绑定不要求重新登记 |

短码为 8 位，10 分钟有效，只能兑换一次；同一请求丢失回执时可恢复同一候选。重新生成使旧的未兑换码失效。码所属班级由网页大屏登录身份决定，本机不能指定其他班级。已占用的大屏不可覆盖，先核实并撤销旧设备。关闭后重新开放、重置大屏登录凭据、改变绑定或学期状态，都不能使未确认的旧申请复活。完成连接后沿用现有凭据、通知、考试和噪音功能；这轮不增加功能权限，也没有新增或代替正式隐私协议。

网页只临时显示短码；设备长期秘密由桌面 Host 保存在当前 Windows 用户的 DPAPI 文件中，网页不持有它们。管理员预授权保存于服务器，不依赖管理员登录会话。服务端沿用严格请求校验、限流、事务锁与审计。协议版本仍为兼容扩展的 N1 `0.1`，增加网页配对路由；新桌面可使用旧审批路线连接旧服务，新网页生成码需要新后端。

## 代码入口

| 仓库 | 入口 |
| --- | --- |
| NPClassworks | `NpepPairingAccess.vue` 管理预授权，`NpepScreenPairingCard.vue` 展示网页码；`classworksV2Client.js` 分开学校账号与大屏凭据 |
| NPClassworksKV | `services/npepScreenPairing.js` 管理授权、短码和兑换；`npepPairingBatch.js` 负责批量预览及事务提交；`npepService.js` 在读取批准及确认时重查有效性 |
| NPEduTools | `NpepConnectionSession` / `NpepConnectionControl` 共用于 OOBE 和设置；`NpepRuntime` / `NpepDevice` 管理请求恢复、确认和凭据 |

HTTP 接口统一以 `/api/v2/npep` 开头：学校管理员使用 `GET /schools/:schoolId/pairing-access`、`POST /schools/:schoolId/screen-bindings/:bindingId/pairing-access`；大屏凭据使用 `GET/POST /screen/pairing`；未配对桌面使用 `POST /pairings/claim`，后续沿用原配对查询及确认接口。`expectedRevision` 防止管理员覆盖旧设置；网页生成和桌面兑换均按请求 ID 恢复。

## 年级／全校批量设置

批量范围限定为后台所选的 **ACTIVE 当前学期**：指定年级只处理其班级；“全校（当前学期）”包含未归入年级的行政班。只处理已存在、启用的大屏及启用的行政班，排除旧学期、停用班级／大屏和非行政班。没有创建大屏账号的班级不会自动创建；以后新增的大屏仍默认未开放，需重新预览并授权。

预览显示学期、范围、有效数量、需修改数量、保持数量、排除数量以及前 50 台明细；超过 50 台时，明确提示提交处理统计中的完整范围。管理员勾选核对后才能提交。切换学校、学期、范围或操作会清除旧预览和确认。

后端新增 `POST /schools/:schoolId/pairing-access/preview` 与 `POST /schools/:schoolId/pairing-access/batch`，使用学校管理员身份，协议仍为 `0.1`。请求包括 `requestId`、`termId`、`targetType`（SCHOOL／GRADE）、`targetId`（全校为 null）及 `enabled`；提交还需 `previewDigest`。摘要覆盖实例代际、目标操作、大屏名单、班级归属、预授权与登录凭据版本。

提交时重新校验管理员会话与归属，在 SQL 事务中锁定学期、班级和大屏并重建摘要；名单或授权变化返回 `409 PREAUTHORIZATION_CHANGED`，整批不保存。只修改状态变化的大屏并递增授权版本，取消其待兑换码；未确认的已兑换申请随版本失效。保持原状态的大屏不递增版本、不取消码；现有连接不撤销。批量审计记录以提交请求 ID 关联本次操作。

批量提交不提供跨请求的结果恢复：成功提交但回执丢失时，界面明确提示“可能已保存”，要求刷新再预览，不盲目重复提交。成功后重用旧摘要重试会被拒绝；单屏修改、网页短码和桌面兑换的原有恢复逻辑保持不变。无需新增批量数据库迁移，沿用上面的预授权字段。
