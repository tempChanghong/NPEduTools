维护者统一入口：`./scripts/test-recording-bundle.ps1`，Windows PowerShell 5.1 和 PowerShell 7 均已实测。加 `-PackageRoot <已解压目录>` 同时检查完整包与两处录制器。每次结果保存在独立 `.artifacts/recording-bundle/<编号>/result.json`；失败不能写成通过，真实设备验收始终单列。这个验证入口不构建桌面应用；原完整打包流程仍使用 PowerShell 7。

程序包模式完全使用包内两处组件及 `third-party/ffmpeg/` 源码材料，不依赖开发机 `.tools`、MSYS2 或 .NET SDK；维护者运行合成媒体测试仍需 Python。日常使用程序包无需 Python，也无需运行验证脚本。Standalone 组件模式则核对指定开发组件目录。

自动回归入口：`./scripts/test-recording-bundle-regressions.ps1 -PackageRoot <已解压目录>`。它用独立副本验证缺失／损坏组件、源码、Python 以及无开发缓存的包；副本和结果保存在 `.artifacts/recording-bundle-regressions/<编号>/`。不改原包、不启动 App、不采集屏幕或声音。该回归入口需要开发组件缓存来生成负例副本，和程序包验证入口的依赖不同。

确定新版本号后，打包执行 `./scripts/package-npedutools.ps1 -ReleaseVersion <新版本号> -ReleaseNotesPath docs/releases/NEXT-FFMPEG.md`。不能省略版本号；已发布版本清单或本地已有同名标签会被拒绝。发布后更新 `scripts/published-desktop-versions.json`；维护者先同步标签，再打包。此前同名本地试验 ZIP 是构建证据，不能上传覆盖旧附件。
