## 使用

**NPClassworks → 学校管理 → 大屏账号 → 打开 NPEP 设备互联 → 学校自习噪音排程。**

选择有效学期和年级／行政班，填写星期与开始、结束时间，先“预览影响”，再“保存排程”。年级无配置默认关闭；班级无配置默认继承年级。班级覆盖不和年级时段叠加，班级关闭不被年级启用。

预览显示有效规则、改变的班级及已配对设备数量，最多列 50 个班级，汇总覆盖全部。配对数量不代表在线或已应用。单学期支持最多 1000 个有效行政班，超出会拒绝加载，不静默截断。

冲突时保留草稿并阻止覆盖；明确重新加载后可继续。网络错误后重试同一保存请求沿用 ID，不重复写入。保存成功后需要再次预览才可再次保存。

**本轮保存不会打开麦克风，也不改变现有手动监测。** 页面明确显示“尚未下发执行”。

## 管理契约与架构

```mermaid
flowchart LR
  Page["学校排程编辑页"] --> API["0.7 管理接口"]
  API --> Auth["管理员与实际目标范围"]
  Auth --> Rules["N4.3a 继承与校验"]
  Rules --> Store["政策版本、请求结果、审计"]
```

接口共同前缀 `/api/v2/npep`，使用管理员 Bearer 登录、`X-NPEP-Version: 0.7` 和请求关联 ID。

| 接口 | 用途 |
| --- | --- |
| `GET /schools/:schoolId/noise-schedules?termId=...` | 有效学期、年级、行政班、已存政策；未给学期时选最近有效学期 |
| `POST /schools/:schoolId/noise-schedules/preview` | 校验草稿及版本，计算影响；不写入 |
| `POST /schools/:schoolId/noise-schedules` | 原子保存、版本递增、请求结果和审计 |

POST 严格字段为 `requestId / termId / targetType / targetId / expectedRevision / policy`。目标类型 `GRADE / CLASS`；未存政策的期望版本为 0。只接受本校有效学期的年级和有效行政班，走班不适用。未知字段、重复 JSON 键、错误类型及超限规则均拒绝。

政策表 `NpepNoiseSchedulePolicy` 的键包括学校、学期、目标类型及 ID；`NpepNoiseScheduleRequest` 保留原始请求结果。现有学校锁串行处理写入，会员和登录会话每次重查。重试返回原始回执，不覆盖后续版本；改变请求内容或换操作者复用 ID 返回冲突。`NpepAudit` 与政策及请求结果同事务提交。

0.6 手动监测和报告保持独立。本轮只开放 0.7 管理接口，未新增设备下发路由或宣告 `noise.schedule` 执行能力。源码入口见 [KV 导读](../../../NPClassworksKV/docs/NPEP-NOISE-SCHEDULES.md)。
