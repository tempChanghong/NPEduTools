# NPEP N1 设备端实现与首轮联调记录

日期：2026-09-20。范围：隔离环境的配对、只读状态和撤销；尚未交付常驻联网与配对 UI，未部署生产。

后续更新：2026-09-21 的设置页和后台实现见 [N1 UI 与生命周期验收](NPEP-N1-UI-REPORT.md)。本文保留上一阶段的实际范围与数字。

## 本轮结果

已从最新发布修订所在 `origin/main`（`2d25809`）建立 `codex/npep-n1-device`，先提交审阅通过的共同契约（`f2dc189`），再在 C 盘隔离副本开发与测试，最后同步源码回 D 盘。没有修改 `InDev-20260920` 发布标签或公开发布包。

设备端新增 `NPEduTools.Integrations.Npep` 库和独立 `NPEduTools.NpepProbe` 入口。实现包括：

- 用户确认服务 origin、实例和部署代际后发起配对；学校管理员批准后，本机再次确认具体学校、班级、大屏及 approvalId。
- 配对候选和设备候选均在首次网络请求前用当前 Windows 用户的 DPAPI 保存。原子替换文件、目录单实例锁、损坏时拒绝覆盖。
- 激活响应丢失后，使用原候选凭据读取 me；若与未提交事务发生竞态，则重发相同 confirm，保持 requestId 和 secret 不变。
- 新运行实例以 statusEpoch CAS 打开会话；本运行遇到会话被取代、身份变化、撤销或版本不支持时停用，不循环抢占。
- 上报只取已有缓存，不含路径、课表、科目、截图、音视频和秘密。上报超时后重新采样，不补发旧心跳。
- 解绑先持久化停用意图，再尝试远端撤销并清除本地凭据。激活回执不确定时先检查候选是否已成为设备；无法确认远端清理时明确返回 LOCAL_ONLY。

Host 仅增加 `host.cached-status` 读取入口，以及不会启动探测的 `SchoolClockMonitor.PeekSnapshot()`。没有引入常驻云端轮询，没有接入远程模式切换、通知显示或录制控制。

详细命令和恢复步骤见 [设备端指南](NPEP-N1-DEVICE-GUIDE.md)。

单元测试的假服务端只用于确定性故障注入，不替代数据库事务验证。真实跨端验收调用的是 KV 隔离服务，不是内存模拟器：仅回环监听的 HTTPS `localhost:34439` 和专用 PostgreSQL 测试库，由 Classworks/KV 负责人准备。测试学校、班级和大屏均为独立 fixture。

HTTPS 使用短期测试证书，仅在验收程序的专用 handler 中以 CustomRootTrust 验证，不写入系统信任库。生产设备 API 与普通 CLI 仍使用正常 TLS 验证；没有“忽略证书错误”设置。管理员令牌和测试 secret 未写入源码、本文或验收输出。

首次真实调用曾在创建配对时得到 `TEMPORARILY_UNAVAILABLE`。KV 负责人定位到 PostgreSQL advisory lock 的 void 返回值与 Prisma 反序列化不兼容，修复查询后重新验收通过。其并发限流修复与服务端数据库测试属于 KV 分支记录，应与本报告一起审核。

KV 负责人已在[服务端实现与验收记录](../../../NPClassworksKV/docs/NPEP-N1-IMPLEMENTATION.md)报告：完整 PostgreSQL 回归 111/111，NPEP 专项最终运行 14/14（含父测试）；包含跨学校权限拒绝、并发确认、撤销/心跳串行化、绑定失效、两个进程共享限流，以及真实 pg_dump/pg_restore 后的外部 epoch 门禁。这些数字来自服务端任务的执行记录，本任务没有重复执行整套后端测试。生产反代、恢复运维接入和实际教室仍待验证。

## 当前限制与后续验收

1. **不是最终 N1 试点交付。** 目前需显式运行 CLI；WPF 现场配对/停用、OOBE、Host 常驻运行协调及学校管理网页尚未在本任务完成。
2. 首次无 Host 联调上报的是 UNKNOWN；补测已确认独立 Host 的真实模式/录制缓存可送达。网络 ONLINE 不代表 ClassIsland 或 ExamAware 已就绪，上报始终区分这些含义。
3. bridgeVersion 暂为 null，现有缓存只提供应用版本，不能冒充插件版本。后续若需要展示，须扩展明确的本地缓存契约。
4. 服务端跨学校、账号权限失效、绑定生命周期、并发撤销、备份恢复 epoch 门禁等以 KV 负责人真实数据库验收为准；本报告的 9 项闭环不能替代整份 N1 验收清单。
5. 下一轮将先把配对、身份确认、在线/离线、失效原因和解绑结果接入设置页，再管理常驻连接、断网恢复与退出流程；之后做两端 UI 和现场验收。
6. 通知与考试模式仍分别属于 N2/N3，不能把当前配对成功当成已获得这两种控制权限。
