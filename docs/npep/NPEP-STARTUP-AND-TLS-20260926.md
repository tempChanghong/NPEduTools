# 启动提权与 TLS 自动恢复

日期：2026-09-26。代码已修改，按用户要求未构建、未运行测试、未触发真实 UAC 或操作正在运行的后台。

## 启动权限

App.OnStartup 在创建主窗口、托盘、配对服务及启动 Host 前调用 StartupElevation：

- 已有管理员权限：继续启动，Host 继承该权限。
- 普通权限：立即通过 runas 请求 UAC，以原参数启动管理员实例，普通实例退出。
- 取消 UAC：退出，不以普通模式继续运行。
- 已有普通权限 Host：核对管道服务端 PID、用户、会话和实际 token 后拒绝复用，提示先完成录制并从旧程序托盘正常停止后台。没有强制杀进程或自动停止录制。

主程序现在拥有独立 app.manifest，保留 asInvoker 作为极短的提权引导入口；正常界面和后台只能在管理员检查通过后初始化。这样保留现有 Windows Run 登录启动引导方式，不给触控辅助程序的共享 manifest 增加管理员要求。登录启动也会出现 UAC，用户取消则应用不运行。

Visual Studio 普通权限 F5 会由程序请求 UAC并启动新的进程，原调试进程退出；要连续断点调试，请以管理员身份打开 Visual Studio 后 F5。首次使用新代码前，应先正常停止旧后台。

## TLS 失败

原问题是 NpepRuntime.Failure 对 SecureConnectionError 设置了永久阻塞，通知循环同时受该标志限制。现在 TLS 失败保留配对，显示 OFFLINE / TLS_VALIDATION_FAILED，并持续退避重试，不再因此进入永久 STOPPED。

间隔基础为 5、10、20、40、60 秒，附加最多 20% 随机抖动；无重试次数上限。HTTP Retry-After 仍受尊重。成功后重置失败计数。系统时间或证书恢复后自动重连。

服务检查因 TLS 失败时会重试原检查。创建/确认配对中断时复用已经持久化的候选记录，通过 resume-create / recover 恢复，不生成新安装身份或秘密，不跳过学校批准和本地确认。新的手动操作会替换此前等待的重试意图。

没有更改证书验证回调、信任存储或 HTTPS 要求；每次尝试仍使用原来的严格验证。用户暂停/解绑、授权撤销、归属改变和会话冲突仍按原规则停止，不被 TLS 重试覆盖。
