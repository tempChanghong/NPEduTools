# 状态上报与互联失败取证修复

状态上报仍和其他互联操作共用串行网络队列。Host 的实时上报在取得队列后才读取本机缓存并计算样本年龄；已取好的 CLI 样本保留原年龄。采样自身超过五秒仍丢弃并重新采样，不把旧数据改成新数据，也不重新配对或抢占其他会话。

所有 HTTP 适配器在读取响应时统一核对请求编号和协议版本。坏的 429／5xx 响应不作为配置、指令、授权或回执使用，但保留临时 HTTP 状态和有效的 Retry-After，允许退避重试。成功响应仍严格验证；真实 401／403、绑定或服务身份变化、会话替换等继续停止。有效的身份拒绝即使使用 503 状态也不会被当成可重试的普通网关错误。

`config/npep/connection-history.json` 最多保存 48 条脱敏事件，读取时只展示最近七天。记录队列等待、慢请求、HTTP 失败、本机失败和恢复；HTTP 事件包含请求编号与到响应头的耗时。请求取消单独记录，不能直接归因于断网。不保存 URL、查询、凭据、口令、原始异常、请求/响应体或音视频。写盘在独立异步队列中，坏文件或写盘失败不会成为凭据故障；关闭时最多等待五秒。

本机只读能力 `npep.diagnostics` 返回这份历史。普通 `npep.status` 和自习状态不增加历史字段，以兼容严格反序列化的旧 App。诊断导出单独请求历史；旧 Host 不支持时仍能导出现有状态。`SAMPLE_TOO_OLD`、`RATE_LIMITED` 等已知错误保留原码，未知字符串继续脱敏。当前连接恢复并清空当前错误后，历史失败仍保留。

隔离验证使用假 HTTP/KV、私有 Named Pipe 和合成缓存，不访问学校服务、数据库或真实传感器。涵盖 6.1 秒自习请求占用队列、无人工重连恢复、坏 503、严格授权拒绝、慢采样、暂停/解绑、坏历史与写盘失败。四班原事件没有原错误码，修复的是已复现链路，不能据此将现场原因唯一归因于它。
