# 大屏上传自习座位表

入口在本机“自习监测”管理页和定时自习座位表查看页。无需本机管理口令；只能向当前绑定本班上传，不提供跨班选择。手动自习不显示座位表入口。查看始终通过按钮，不自动打开、不加入作业轮换。

1. Host 核对当前在线设备、会话、已应用学校配置和本班图片版本；App 取得十分钟有效的本机票据。
2. 用户选择 PNG/JPEG。原图不超过 8 MiB、最大边 4096、最多 600 万像素。工作线程去除来源元数据，合成白色背景，重新编码 PNG；上传不超过 2 MiB，预览最多 960 像素宽。
3. 明确点击上传或覆盖。App 在自己的 LocalAppData/NPEduTools/seating-transfer 目录写入随机 GUID 文件；Pipe 仅发送票据、GUID、版本、尺寸、字节数和 SHA256，保留 64 KiB 帧上限。Host 不接受任意文件路径。
4. KV 从设备绑定推导学校、学期、班级，不接收客户端提供的这些范围。新 HTTP 接口仍属于独立 0.14 座位表命名空间：
   - POST /device/study-settings/seating/upload-status
   - POST /device/study-settings/seating/upload
5. 设备与后台发布共用学校事务锁和 expectedRevision。并发只允许当前版本的一方成功；冲突保留草稿，须重新核对并主动确认，没有自动覆盖或自动调大版本号。
6. 断线/回执丢失保留同一上传 GUID、内容和预期版本重试。KV 用请求 ID 去重；版本表保存 device:<设备ID> 来源，审计记录 DEVICE_SEATING_PUBLISHED。本机票据失效或 Host 重启后，需重新核对版本，不能用旧票据覆盖。
7. 保存成功表示服务器已保存，不代表大屏已展示。沿用清单下载和新鲜展示回执；正在查看的旧图保持至关闭后切换。撤回会清除旧图，空页仍保留明确上传入口。

新建能力复用现有座位表版本、审计表，无需增加迁移。未部署；真实数据库事务、学校互联网络和一体机验收另行进行。自动验证使用合成图片、本机私有 Pipe、回环 HTTP 和内存持久化适配器，不启动麦克风、摄像头或生产 Host。
