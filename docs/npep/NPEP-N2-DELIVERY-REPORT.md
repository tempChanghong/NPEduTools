# NPEP N2：HTTP 通知投递

日期：2026-09-24。范围：NPEduTools 桌面端实现与隔离验证；NPClassworks/KV 由既有协作任务负责。本轮不推送 main、不部署生产。

## 使用方式

完成过学校互联配对的设备升级后自动接收当前绑定范围内的有效通知，不需要另外申请通知授权。学校网页不必保持打开；NPEduTools 程序必须运行，收起主窗口仍可显示通知。

学校发布通知后，默认约 10 秒后进入大屏；网络故障、分页或已有未关闭窗口可能增加延迟，因此不把轮询描述成严格的实时送达保证。

次要通知可关闭网页/桌面弹窗，但依然进入“设置 → 学校互联 → 学校通知”列表。普通、重要和紧急通知沿用原业务规则弹窗。显示采用四级纯色大字白字，置顶，无声音，需要手动关闭。当前窗口不被新通知抢占；等待队列按级别从高到低、同级按发布时间排列。

“暂停互联”同时暂停通知接收与状态上报，保留配对。恢复后先重新核验；解除绑定或管理员撤销会停止两者。

## 协议与数据

- 原 Bearer 凭据继续使用；既有 N1 `device.status` 能力与 0.1 路由不变。
- `GET /api/v2/npep/device/notifications` 和 `POST /api/v2/npep/device/notification-receipts` 使用 `X-NPEP-Version: 0.2`，保留请求 ID 校验、HTTPS 证书验证、禁止重定向和体积上限。
- 每页最多 20 条，客户端最多接受 500 条；只有所有页面成功、快照 ID 一致、无重复 publicationId 时才替换收件箱。分页失败不会把半份列表当作完整快照。
- 服务端限制整个快照 2 MiB。标题 160、正文 8000、来源 120 均按 UTF-16 码元计数，与 C# `string.Length` 和 JavaScript `.length` 一致。
- 通知日期使用服务端时间及本地单调时钟推算；不使用 ClassIsland 的校铃偏移来决定学校通知是否过期。
- 去重范围含服务地址、服务实例、部署代际、设备、班级绑定及凭据代际；具体消息按 publicationId + revision 区分。修订后的版本可重新提醒。
- 设备凭据仍由 Host 单实例持有。收件箱和待上传回执保存在同目录 `npep.notifications.dpapi`，使用 Windows 当前用户 DPAPI 加密，并在临时文件刷新后原子替换。App 不持有云端凭据。
- 本地 IPC 帧上限仍为 64 KiB，每次最多返回十条简要标题与一条完整正文。列表可翻页。未变动的轮询快照不反复写盘。

回执含义：

| 阶段 | 何时记录 | 不代表什么 |
| --- | --- | --- |
| RECEIVED | 完整通知已持久化到设备 | 不能表示窗口已出现 |
| DISPLAYED | 窗口内容实际渲染 | 不能证明老师看到或读懂 |
| DISMISSED | 用户手动关闭，状态已持久化 | 不能把程序退出算作关闭 |

每个回执事件有稳定 eventId。断线或上传响应丢失后重试同一事件，不生成新的虚假展示记录。按批逐项处理 ACCEPTED / DUPLICATE / REJECTED；数量、关联关系或格式不正确的回执响应不能清空本地待发队列。服务端拒绝会保留明确提示。

## 故障与展示边界

- 旧服务端缺少新接口：提示服务未提供通知，N1 状态继续上报；不会要求反复配对。
- 重启：保留已关闭状态及待发回执，但须先取得完整在线快照才能再次弹窗。
- 网络错误：退避重试并保留配对。已落盘消息不会因回执上传失败而被压制。窗口的有效性无法核实后隐藏旧正文，保留手动关闭入口。
- 撤回、过期或修订：旧内容不再进入待显示队列；已经显示的窗口替换为失效说明，由用户关闭。它不是“已读”回执。
- 管理员撤销/绑定变化：复用设备授权失效路径，暂停通知和状态上报。
- 锁屏/安全桌面：检测不到可交互桌面时不创建新弹窗；不尝试覆盖安全桌面。真实锁屏、混合 DPI、多显示器及班级大屏待现场验收。
- 存储损坏/写入失败：保留原文件，提示错误，不伪报持久化成功。上限为 500 条当前消息、10000 个消息版本记录、5000 个待发回执和 16 MiB 加密缓存；达到上限提示处理，不静默删除待发回执。
