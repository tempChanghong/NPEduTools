# 原生自习双阈值与纪律提示

读取既有 `StudyNoise` 设置，没有新增远程协议、数据库模型或迁移。默认持续高线 5 秒、提醒间隔 600 秒；高/中电平保留管理员已保存值，不预填或校准。数值是 dBFS，不能解释为教室声压级。

- `NoiseService.Receive` 对每个原生 `NoiseMeter` 能量帧调用 `StudyNoiseThresholds`（正常 100ms）。不保存 PCM。电平等于阈值即算达到；数字静音、无效帧、中/低电平会重置连续高线计时。帧间空档大于 500ms 也重置；超过一秒的旧帧不能保持边缘效果。采样累计时间和单调经过时间必须同时满足设置值，缓存查询和集中交付的缓冲帧不能充当五秒真实持续。
- `StudyDisplayService` 只观察已有定时会话。学校配置有效、时钟正常、Active、Schedule 所有权、匹配会话且信号新鲜才返回本地 `StudyThresholdState`。手动、准备、暂停、考试、失效配置/时钟均不授权。无高线配置不触发；中线可留空。
- 中线为较轻的无声边缘渐变，高线即时加重；连续高线达标后才生成五秒内有效的提醒候选 ID。开始后的前五秒保留阶段提示优先权。
- 正式 `StudyWindow` 通过 Named Pipe 请求 `study.reminder / Discipline`，携带展示实例、版本、时段、会话及候选 ID。Host 再次核对当前帧并单次消费，先保存冷却记录再授权声音；相同或过期候选、另一个 App 的重复申请和隐藏后的申请均拒绝。冷却不因配置刷新、App 重启、收起或采集会话更换重置，新绑定范围独立。
- App 收到允许后才显示深红“注意纪律”和现有 `exam-alert.mp3`；持续五秒，作业轮换暂停。准备、开始、结束优先，延迟到达的许可不会打断它们。安静下来会撤下边缘红光，已显示的提醒仍按五秒结束；会话替换、信号/时间失效、隐藏会撤下提醒。提示不包含摄像头状态。
- 四条静态渐变及仅在档位变化时执行的 260ms 淡入，无全屏模糊、循环闪烁、新采集线程或浏览器进程。现有文字光晕仅覆盖字形。

- `StudyReminderStore` 在正式 Host 数据目录的 `npep/study-reminder-state.json` 保存绑定范围的 SHA256 和已经过秒数，不保存账号凭据、原音频或墙上时间。默认 600 秒冷却使用单调时钟；冷却中最多每 30 秒保存一次，跨过当前配置的结束点时另保存一次。完整 Host 重启只恢复已保存进度，不计离线时间及最后未保存的进度，所以可能延长等待，不会因 Windows/学校时间跳变提前放行。日志最多 16 个绑定范围、8 KiB，充分过期的范围才清理；沿用正式 Host 的单实例互斥，多个 App 的申请由 Host 串行消费。
- 保存失败、读取损坏或范围容量用尽时停止授权纪律播报，界面显示“纪律提醒暂不可用”，定时采样和中/高线红光继续。损坏原文件保留，当前进程不自动清空重试。记录更新使用临时文件、刷盘及替换，声音许可晚于成功保存。

实现边界：摄像头仍是占位；没有捕获或上传照片、音频。声压级校准、现场阈值/增益及实际大屏视听和整体内存验收留待用户。隔离测试中的新进程、HTTP、Named Pipe 和 WPF 验证不等于真实大屏或线上验收。
