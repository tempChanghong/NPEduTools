# 本机自习监测设备准备

主目录已接入原生 WPF 自习展示。首次设置中，选择学校互联或噪音监测用途都会出现“配置监测设备”步骤；已经完成的向导不强制重新弹出。已有用户可从“设置 → 打开初始设置”重新进入，或从首页、左侧“监测 → 自习监测”调整设备。

## 选择与保存

- 麦克风复用 `NoiseService` 的固定设备 ID 与原有监测配置，手动监测和学校自习使用同一份监测麦克风选择。此处不改录课设备。
- 摄像头使用 Windows Media Foundation 枚举，保存不透明的视频设备符号链接 ID 到 Host 数据目录的 `study-camera.json`。同名设备在列表中附序号区分；保存依据 ID。
- 摄像头可选择“暂不使用摄像头”。向导继续前需要核实已保存、当前可枚举的监测麦克风；未保存的选择不会被当成完成。仍允许用户明确跳过该步骤。
- 麦克风和摄像头分别保存并确认结果，未确认的写入不自动重试。已保存设备拔出后保留 ID，不改用另一个设备。
- 监测处于 Starting、Active、Stopping 时不能修改设备；摄像头列表刷新不代表权限、成像质量或实际捕获已验证。
- 配置损坏、保存失败、Host 重启造成版本变化、设备在保存前拔出均显示失败并保留原选择或原文件；页面隐藏或离开后忽略旧异步结果。

## 本机接口

| 能力 | 行为 |
| --- | --- |
| `study.devices.status` | 读取摄像头偏好，不枚举、不捕获 |
| `study.devices.refresh` | 刷新原生摄像头目录，不激活媒体源 |
| `study.devices.select` | 用 Host 实例 ID 和修订号保存或清除摄像头选择 |
| `study.devices.microphone` | 复用噪音设备枚举并保存监测麦克风，仅允许 select，拒绝 start/stop |

新增管道字段为空时不序列化，旧请求与响应格式继续兼容。学校排程、阈值及展示策略仍由学校后台配置，本机页面不另建排程。

摄像头实现仅调用枚举接口，不调用 `IMFActivate::ActivateObject`，不预览、不拍照、不上传。微软说明：[枚举视频捕获设备](https://learn.microsoft.com/en-us/windows/win32/medfound/enumerating-video-capture-devices)。现有摄像头状态图标仍是占位，不能表示照片已捕获。

## 验证边界

设备与 OOBE 测试使用独立 Named Pipe、合成设备目录和临时配置，不开启真实麦克风或摄像头。另做只读 Windows 枚举探针，核对本机设备 ID 的唯一性与重复枚举稳定性；不记录设备名称或 ID。

实际大屏上的设备权限、音频输入、声音提示、ClassIsland 时间、长期资源占用和现场使用仍需人工验收。dBFS 不等于声压级，校准以及照片捕获、上传和保留策略的执行不在本轮完成范围。
