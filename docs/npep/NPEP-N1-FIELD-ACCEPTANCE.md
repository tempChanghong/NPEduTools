# NPEP N1 现场验收与上线前检查

日期：2026-09-21。用途：把开发电脑上的隔离结果与班级大屏现场结果分开记录，供下一次发布审核和现场操作使用。N1 仅授权 `device.status`，本表不验收远程通知、考试模式切换或录制控制。

## 当前状态与发布边界

用户确认采用 Docker 分离部署：网页为 `https://newfires.top`，API 为 `https://api.newfires.top`。当前开发电脑不是班级大屏。NPEP 实现在功能分支，**main 才触发 server.js 自动部署；合入并推送 main 是生产发布动作**。功能分支已推送并完成托管检查；当前未合并或推送 main、未部署、未线上配对。

本轮仅发出公开 `GET /api/v2/npep/info`，不带身份凭据；使用系统 TLS 验证、禁重定向，携带协议版本与随机请求 ID。

| 地址 | 2026-09-21 实测 | 解释 |
| --- | --- | --- |
| `https://newfires.top/api/v2/npep/info` | TLS 通过；200、text/html | 网页响应，不是配对服务 |
| `https://api.newfires.top/api/v2/npep/info` | TLS 通过；404、application/json，无 NPEP 信封 | 功能分支尚未发布背景下的预期未上线状态，不据此判定部署故障 |

未来设置页应填写 **`https://api.newfires.top`**，不附加 `/api/v2/npep` 或其它路径。正式服务需要先满足下列发布条件，再做现场配对。不能把 HTML 的 200 或普通健康检查成功当作 NPEP 就绪。

## 发布审核之前

服务端操作以 [Docker 分离部署准备记录](../../../NPClassworksKV/docs/NPEP-N1-DEPLOYMENT-READINESS.md) 为准，重点检查：

- 固定并记录三个仓库待发布提交、迁移审阅结果和构建结果。Windows CI 与 `pnpm test:e2e:npep` 网页专项门槛已取得 [实际托管通过记录](NPEP-N1-HOSTED-CI-REPORT.md)，后者强制启用隔离 NPEP 并拒绝跳过。后续代码或发布组合发生变化时，应重新验证受影响检查。
- Docker 必须显式接入 NPEP 开关、配置路径和独立持久化目录；仅给宿主机 env 增加变量不够。目录需允许容器运行用户原子替换文件，且不随数据库备份一起恢复。
- 初始外部配置保持关闭。普通更新不重新生成实例/代际；首次激活、恢复前关闭和代际轮换、恢复后失效旧授权分别审核。
- 宿主机恢复脚本与容器内的 NPEP 开关一致；实际自动部署使用审核过的配置。不要提前合 main 再补恢复保护。
- 分离域名的 API 构建地址、CORS、Authorization/版本/请求 ID 头和路由转发已核对。反代共享配对额度须满足试点规模。

本表不授权现在执行生产迁移、激活或合并。完成材料后先审核发布，再执行受控试点。

## 双端现场验收表

每项填写通过/失败/未测、时间与现象；未测项保持未测，不能用本地自动测试代填。

| 编号 | 操作 | 应观察到的结果 | 现场结果 |
| --- | --- | --- | --- |
| F01 | 大屏打开“设置 → 学校互联”，检查 API origin | 正常系统 TLS 通过；版本 0.1、请求 ID 匹配、身份与管理员核对一致；仍未上报 | 未测 |
| F02 | 本机核对服务并创建配对码；管理员在网页解析、选定测试绑定并批准 | 网页显示设备、班级；设备显示同一学校/班级/大屏；未进行本机第二次确认前不能开始上报 | 未测 |
| F03 | 本机核对归属并确认连接；网页刷新列表 | 同一登记出现新接收时间和只读状态；内容与现场一致，自动录制启用状态不等同于正在录制 | 未测 |
| F04 | 收起主窗口，保留后台，等待至少两次 20 秒上报周期后刷新网页 | 接收时间继续前进，重新打开设置页显示同一配对 | 未测 |
| F05 | 暂时断开大屏网络超过 60 秒；从独立联网的管理员设备刷新网页 | 大屏保留配对并说明重试；学校端显示离线/失联和上次观测，接收时间不前进 | 未测 |
| F06 | 恢复网络，等待自动退避结束并刷新网页 | 不需重新配对；原 deviceId 恢复在线，上报恢复时的新状态。退避最高 60 秒加抖动，请求另有超时；尊重服务端 Retry-After | 未测 |
| F07 | 暂停上报，正常退出 NPEduTools，重新启动，再恢复上报 | 重启仍暂停、不联网；现场点击恢复后原绑定重新连接 | 未测 |
| F08 | 在未暂停状态正常退出 NPEduTools，重新启动 | 使用原配对恢复，出现新的接收时间，无重复 ACTIVE 登记，不争抢旧进程会话 | 未测 |
| F09 | 保存其它内容后休眠/恢复；不支持休眠则记录“不适用”及原因 | 恢复后旧在线观测不冒充新回执；网络可用后恢复新鲜上报，不积压休眠前样本 | 未测 |
| F10 | 现场人员在约定时段重启 Windows，登录原用户 | 凭据可读；按既有自启动设置自动运行或手动启动后恢复。不要把“未配置开机启动”记作 NPEP 丢配对 | 未测 |
| F11 | 管理员撤销测试登记，再恢复网络/重启设备端 | 上报停用，旧凭据不恢复授权，不自动创建配对或夺回会话 | 未测 |
| F12 | 本机解除绑定，网页确认登记已撤销 | 本机停止上报并清除凭据；LOCAL_ONLY 必须继续由管理员确认远端撤销，不能记成双端成功 | 未测 |

网页使用显式刷新。不要因为网页还显示“上次观测在线”就认定新的上报仍然成功；核对接收时间和页面过时提示。60 秒在线窗口以服务器收到的新样本为准，学校铃声校准时间不参与认证和连接新鲜度。

如出现错误，记录错误码和上述无秘密环境信息；先保留原配对候选，不反复创建配对。TLS 失败先核对地址、Windows 时间和服务端证书，不安装未知根证书或跳过验证。现场网络、休眠和重启都由现场人员在约定时段实施；本任务没有远程改变这些系统设置。

## 本地自动验收的范围

新的隔离验收程序使用真实 HTTPS 与 PostgreSQL，在测试传输层制造断线与“服务端已接收但设备丢回执”，检查离线、新采样和恢复；再启动独立测试进程，检查正常退出和突然终止后的 DPAPI 与会话恢复。它仅终止自己创建的测试进程，不终止正式 Host，不更改网卡、系统时间或证书信任，不关机。

这些结果覆盖协议和后台运行逻辑，**不等价于 WPF 双界面现场验收、真实网卡断线、设备睡眠、Windows 重启或生产反代验收**。具体执行结果见 [本地韧性验收记录](NPEP-N1-RESILIENCE-REPORT.md)。
