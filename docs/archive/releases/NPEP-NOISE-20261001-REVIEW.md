## 功能边界

NPClassworks 管理开始／停止请求、学校年级／班级排程与报告展示；KV 保存政策、设备状态、回执和统计；NPEduTools 独占采集麦克风，计算 dBFS、执行学校排程并补传统计。网页在原生接管后停用旧网页采集和定时功能，断线不自动退回网页采集。

不保存或上传原音频，不涉及摄像头。dBFS 是输入信号电平，不是校准后的实际声压级，也不作班级评分／排名。手动监测最多三小时；自动监测采用 ClassIsland 学校时间，缺少可靠学校时间时等待／停止，不改用 Windows 时间。

配对即授权当前学校能力；仍需本机保存麦克风并保持 Host 运行。保存规则不等于已应用，更不等于已打开麦克风。手动停止自动会话会跳过本次窗口，明确恢复后才重启；考试与模式切换暂停自动会话，不接管手动会话。

## 发布顺序与恢复

1. 审阅三仓完整差异，区分 N3、N4、开发环境和品牌改动；排除私人配置、令牌、数据库、临时方案及缓存。确定版本，形成可重建的完整提交组合。
2. 在最终组合运行 `scripts/test-npep-n4.ps1 -Browser -Database`；同时保留既有 N3 验收，补全仓库 CI、网页生产构建／PWA 和桌面发行包检查。当前结果仅覆盖之前的工作区。
3. 更新前核实现有部署代理、实际提交对与备份新鲜度；备份数据库、配置、现运行镜像，保留 NPEP 身份及配置卷。无需再次首次激活。本轮没有远程核查这些事实。
4. 沿用生产部署方式受控更新 KV 与配套网页，检查迁移完成、原作业／通知／学校管理正常。本地调试继续使用原生 PostgreSQL，不用生产库或 Docker 探索问题。
5. 更新一台试点桌面。**先核查已保存的年级／班级规则与继承关系**，避免旧规则在新版 0.7 桌面上线后意外开始采集；仅配置明确的试点范围，现场完成 N4.3d 后再扩大。
6. 故障时停止扩大试点，回退上一受测应用提交对，新增表先保留。恢复数据库会丢失备份后的数据，不能作为普通应用回退自动执行。应用回退不撤销已下发规则或桌面的模式状态；现场先停止自动监测，再核实设备状态。

已确认规则可在当前 Host 内离线执行，租期最长 24 小时且要求学校时间可靠；重启／暂停互联不继承旧租期，需重新在线确认。**服务端关闭规则或撤销设备无法瞬间通知离线设备**；需要立即停止时使用本机停止。不能把服务端回退承诺为所有离线设备立即停止。
